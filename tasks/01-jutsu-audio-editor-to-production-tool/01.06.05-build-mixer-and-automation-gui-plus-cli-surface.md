## Notes

- 2026-08-19: `src/mixer_panel.rs` draws one strip per track and bus — level, pan, mute/solo, a
  peak meter, routing, and the effect rack with bypass, reorder and an add menu built from the
  registry. It mutates nothing: every control reports an action and `apply_mixer_action` turns it
  into a command, so a fader move undoes and reaches an attached session like any other edit.
- 2026-08-19: meters come from the mixdown (`mix_project_metered`) through the worker. They are
  static levels for the rendered mix, sitting next to the transport's live peak rather than
  replacing it.
- 2026-08-19: the CLI gained the whole surface — routing, strips, effect racks with schema
  discovery, and automation lanes — in `src/cli_mixer.rs`, validating through the same
  `parameters` API the GUI uses.
- 2026-08-19: automation lane *drawing* in the timeline is not there yet; lanes are created and
  edited from the CLI, and rendered by the mix. The strip UI is where a curve editor will hang.
