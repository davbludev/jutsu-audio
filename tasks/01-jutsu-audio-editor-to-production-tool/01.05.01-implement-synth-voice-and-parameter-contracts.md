Define note/trigger lifecycle, polyphony, sample-rate handling, parameter metadata, state serialization, and deterministic reset.

## Acceptance

Reference oscillator/noise synths work through registry in real-time and offline.

## Notes

- 2026-08-19: `Synth` is now `prepare` / `reset` / `render(events, output)`. Events carry the frame
  inside the block they land on, so a note is sample accurate rather than block accurate, and
  `reset` is what makes an offline render reproduce a real-time one.
- 2026-08-19: `voice.rs` holds the shared pieces — note events, a linear attack/release envelope,
  and seeded xorshift noise. `builtin.rs` has the two reference synths (`builtin.oscillator`,
  `builtin.noise`), 16-voice polyphonic with quietest-voice stealing.
- 2026-08-19: state serialization stays where it already was: a synth is rebuilt from its
  descriptor's `state_version` plus its stored parameters, so there is no second serialization
  path for instances to drift through.
