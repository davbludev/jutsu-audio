Effect parameters are read once at instantiation and are fixed for the whole render, and
`apply_strip` in `crates/jutsu-audio-engine/src/mixdown.rs` only ever reads `gain_db` and `pan`.
A filter sweep — the single most recognisable gesture in modern sound design — cannot be
expressed at all.

Two halves:

- `AutomationTarget::Effect`, so a lane can name an insert and one of its parameters.
- A block-wise render in `apply_chain`, setting parameters from the lanes before each block, and
  an `Effect::set_parameter` hook with a default that keeps existing extensions working.

## Acceptance

A lane over an insert's parameter changes what is heard, offline and in playback identically;
an extension that does not implement the hook still renders; the schema migrates.
