Define parameter units/ranges/defaults, interpolation, automation lanes, breakpoints, and sample/block evaluation.

## Acceptance

Synth/effect/mixer parameters use one API; GUI/CLI edits validate identically.

## Notes

- 2026-08-19: `crates/jutsu-audio-extensions/src/parameters.rs` is the one parameter API.
  `ParameterDescriptor` gained a `unit`, and `strip_parameters()` describes the mixer's own
  parameters in exactly the same shape an extension uses — so `validate_named` is what both the
  GUI and the CLI call, and neither can accept what the other rejects.
- 2026-08-19: automation lives on the project as lanes of breakpoints with `step` and `linear`
  curves. Evaluation is per frame, not per block: a fader move is a curve, and stair-stepping it
  would put back the clicks the snapshot crossfade exists to remove.
- 2026-08-19: a lane overrides the stored value it automates; an empty lane leaves it alone. That
  keeps "automated" and "set" from fighting over the same parameter.
- 2026-08-19: commands `AddAutomationLane`, `RemoveAutomationLane` and `SetAutomationPoints`
  (whole-lane, so drawing a curve is one undo step), each with an inverse.
