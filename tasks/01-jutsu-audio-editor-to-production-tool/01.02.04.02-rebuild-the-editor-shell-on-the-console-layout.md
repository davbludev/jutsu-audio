Replace the first-pass GUI with a dense engineering layout, and remove the controls that were
painted but never wired.

## Objective

The original shell had five structural problems. Controls that did nothing — the search box was
bound to a throwaway `String` and marked non-interactive, the rail's "S" and "P" were plain
labels, "Snap Smart" was static text, and the level meter was hardcoded to 62%. Clip waveforms
were procedural sine noise, while the real peaks written to `.jutsu-audio-cache` at import were
never read back. The timeline had no scroll or pan, so anything past the window edge was
unreachable and the "Pan" tool was a label. The transport floated on top of the timeline and
covered clips. And a 58 px rail plus a 292 px library plus a 310 px inspector left the work
surface squeezed between them.

Playback also only ever rendered the selected clip, from its own sample zero, while the playhead
was drawn from the timeline origin — so a clip starting at two seconds played with the playhead
at zero, and Export wrote one clip rather than the arrangement.

## Acceptance

Console treatment: one saturated colour that always means playhead-or-selected, 2 px radii,
monospace numerics, hairline rules. Every control on screen does something or is not there.
Waveforms come from the cached peaks. The timeline scrolls, pans and zooms about the pointer,
with a working snap grid. The transport is docked in the status bar next to a real peak meter.
Play and Export consume the same full-timeline mixdown, so the playhead, the audio and the
exported file agree.

## Notes

- 2026-08-19 — Split the shell into `src/theme.rs` (palette, egui style, shared drawing),
  `src/timeline.rs` (view state, painting, interaction; returns a `TimelineAction` rather than
  mutating) and `src/worker.rs`, leaving `src/main.rs` as app state and chrome. Added a mixdown
  step on the worker that sums every clip into one interleaved stereo snapshot at the project
  rate, which both playback and export read; clip frames are now project frames, so material at
  another rate is converted when it is placed. Introduced a per-clip inspector edit buffer keyed
  by clip id, which fixes gain leaking between clips when selection changed by any path other
  than a timeline click. Track headers show name, layer and clip count only: mute, solo and track
  gain are deliberately absent because there is no command to change them and the render path
  would ignore them. Removed the unconditional 33 ms repaint. `jutsu-audio <project.json>` now
  opens a project at startup. Verified against a demo project built through the CLI: four clips
  from two real assets draw cached peaks, Fit frames the arrangement, selection fills the
  inspector with the clip's own values, and playback advances the playhead with the meter
  reading -19.4 dBFS at xrun 0. `cargo quality` passes.
