B01 moved clip decoding to a worker, but every other blocking operation still ran inside
`eframe::App::update`, so ordinary editing hitched and file dialogs froze the window.

## Objective

Four paths still blocked the UI thread:

- `apply()` called `persist()` on every successful command, so each clip drag, gain nudge,
  split and delete performed a full project validation, `serde_json` serialization and atomic
  write with an fsync before the frame could finish.
- `AssetManager::prepare_wav_import` ran inline: read the whole file, SHA-256 it, decode it,
  build peaks, serialize the peak cache and copy the source. It also opened the file twice,
  once for the hash and again for the decode.
- `OfflineExporter::export_wav` and `ProjectStore::open` ran inline.
- `rfd::FileDialog::pick_file` blocked the event loop for as long as the dialog was open, which
  Windows reports as "not responding".

The app also called `request_repaint_after(33ms)` unconditionally, so it never idled.

## Acceptance

The UI thread only draws and dispatches. Saving is debounced and runs on the worker; import,
open, export and every file dialog run there too. Decoded samples are cached across mixdowns so
adjusting a clip does not re-read the file. Repainting is on demand, continuous only while the
transport is playing, a meter is decaying, or a mixdown is in flight.

## Notes

- 2026-08-19 — Added `src/worker.rs`: one background thread taking a `Job` and returning a
  `JobResult`, with an LRU cache of decoded files against a fixed sample budget. File dialogs use
  `rfd::AsyncFileDialog` driven by `pollster::block_on` on that thread, which is the portable way
  to open a picker off the main thread. Import chains the "choose a project location" dialog
  ahead of the WAV picker when the project has no path yet, so the whole flow is one job.
  `apply()` no longer writes to disk: it stamps a save deadline and a mixdown deadline, and
  `dispatch_pending_work` fires them once editing settles (700 ms and 150 ms). `prepare_wav_import`
  now decodes the bytes it already read instead of reopening the file, and the peak cache is
  written compactly rather than pretty-printed. `cargo quality` passes.
